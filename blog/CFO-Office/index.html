01 — The thesis

Most founders treat the CFO function as a hiring problem. It isn't — not yet.

Before you can justify a full-time CFO, what you actually need is leverage — the ability to run a tax scenario, refresh a cash forecast, pressure-test unit economics, hunt for leaks, and model an exit, repeatedly and cheaply.

That is not one job. It is five disciplines that happen to report to one person. And five disciplines is exactly what an orchestrated agentic workflow is built to handle.

This guide shows how to assemble a Claude CFO Team — an orchestrator plus five specialist agents — on the low-code surface of Claude Projects + Skills. You start by clicking buttons. You finish with versioned skill files, deterministic code for the math, and a governance layer that keeps a regulated profession safe.

One honest line up front. This does not replace your Chartered Accountant's signature or your judgment. It compresses the 80% of analysis that is mechanical, so the human 20% — judgment, sign-off, accountability — is faster and sharper. Built that way, it is an asset. Built as an oracle, it is a liability.

05 — The build guide

From first click to a governed, board-ready workflow

Six steps. The first you can do today; the last makes it safe to publish across a team. Code is real and adaptable.

01
Set up the workspace

Turn on the engine, then create the Project

Skills run on Claude's code-execution sandbox, so that switch comes first. Then the Project becomes your "firm" — its instructions are the orchestrator, its knowledge base is the shared books.

  • Enable Code execution / file creation in Settings, and confirm Skills is on under Customize → Skills.
  • Create a Project named specifically — CFO Team — [YourCo], not "Finance".
  • Decide data hygiene first: prefer trial balances and templates over raw transaction dumps; keep the DPDP Act in mind. If you wouldn't email it to a new contractor on day one, don't upload it.
02
Install the orchestrator

The Managing Partner lives in the Project instructions

This persistent instruction does four jobs: set the firm's standards, route requests to the right specialist, enforce output discipline, and draw the human sign-off line. It fits comfortably under the ~8,000-character limit.

project → instructionsorchestrator

Pair it with a tight knowledge base: chart of accounts, a trial-balance template, a tax profile (entity type, regime, DPIIT/80-IAC status, GSTINs), the cap table, and a metric glossary. Curation beats volume — twenty precise pages beat two hundred noisy ones.

03
Build the five specialists

Each agent is a Skill — a folder you ZIP and upload

Five rules make a skill reliable: the description is the trigger (write what it does and when to use it), keep the body lean (~3,000 tokens), push deterministic math into scripts, give it one job, and let composition handle cross-functional work.

cash-flow-forecaster/SKILL.mdskill

And the math it runs — a real script, executed in the sandbox, so a balance is never "estimated" by a language model:

cash-flow-forecaster/scripts/runway.pypython

Repeat for the Tax Strategist, Margin Analyst, Profit Leak Detector and Exit Planner. ZIP the folder (so the archive holds cash-flow-forecaster/SKILL.md, not a loose file) and upload via Customize → Skills → "+" → "+ Create skill."

04
Orchestrate the team

The workflows that pay the rent

Describe the task and let the descriptions route it; name a skill explicitly when you want a specific lens.

05
Test until it fires

The one failure mode worth pre-empting

The commonest problem is a skill that doesn't trigger — and the fix is almost always the description. Run an acceptance matrix where every prompt should invoke the right skill without you naming it. If one misses, add the words a user would actually type to that skill's description and re-test.

  • Force the math through scripts — the orchestrator forbids free-hand arithmetic. A language model should not be your calculator.
  • Guard tax claims — require a cited section and a "position to confirm" flag on anything contestable.
  • Always surface assumptions — a finance answer with hidden assumptions is worse than none.
06
Govern, then publish

What makes it safe to share across a team

Version each skill like a controlled document with a changelog, and review them every Finance Act / GST cycle — the tax anchors drift. On Team and Enterprise plans, an owner can provision all five skills organization-wide, so everyone runs the approved version. Keep source files in the knowledge base so every conclusion is traceable to its inputs.
